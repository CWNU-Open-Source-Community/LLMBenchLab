# Phase 4：LLM Judge、Pairwise、个人 Arena 与长上下文

- 状态：`planned`
- 前置阶段：Phase 2 的可靠执行能力；复用 [Phase 3](PHASE-3-BENCHMARKS.md) 的插件与数据版本机制
- 后续阶段：[Phase 5 — Agent & Live](PHASE-5-AGENT-LIVE.md)

## 阶段目标

为开放式回答建立可校准、可审计的 LLM-as-a-Judge 和成对比较能力，提供匿名个人 Arena，并用长度分桶、截断检测和成本追踪支持长上下文评测。

## 功能范围

- Judge rubric、结构化输出、配置快照、有限重试和校准集。
- Pairwise Judge：左右顺序互换、平局、冲突与位置偏差分析。
- 个人 Arena：匿名模型、随机左右顺序、投票与撤销审计、基础排名。
- Judge 模型/Prompt/参数/版本/原始输出和费用的完整追踪。
- 长上下文 retrieval、needle、综合任务；按实际上下文长度分桶。
- 截断检测、上下文窗口校验、Token/延迟/成本预算和结果可比性提示。

## 非目标

- 不宣称 Judge 分数等于绝对质量或真实人类偏好。
- 不建立公开众包 Arena、商业榜单或未经校准的单一综合排名。
- 不实现 Agent 工具调用、多用户鉴权或公共部署。

## 依赖

- Phase 2 的持久任务、预算、取消、重试和审计能力。
- Phase 3 的插件、数据版本与分组指标机制可用；不强依赖代码沙箱。
- 获得可合法使用的人工校准样本、rubric 和 Judge 模型访问方式。

## 验收标准

- [ ] 每个 Judge 结果可追溯到模型、rubric、Prompt、参数、协议、原始输出和费用。
- [ ] Judge 解析失败、拒答、超时与上游错误分开记录，不静默补分。
- [ ] Pairwise 左右互换测试可量化位置偏差；平局和冲突有明确语义。
- [ ] 校准集、预先登记的质量门槛和重复运行稳定性报告齐全。
- [ ] Arena 默认隐藏模型身份、随机左右顺序，投票修改有审计记录。
- [ ] Arena 排名同时显示样本量和不确定性，不输出虚假精确度。
- [ ] 长上下文按实际 Token/长度分桶展示准确率、失败、延迟和成本。
- [ ] Judge、人工投票与客观分数分栏呈现，不同版本不混排。

## 风险

| 风险 | 应对 |
| --- | --- |
| Judge 自偏好、风格和位置偏差 | 顺序交换、多次/多 Judge 对照、人工校准、披露偏差 |
| Prompt 或模型更新导致漂移 | 完整快照、固定版本、定期再校准、禁止跨版本混排 |
| Arena 样本少而排名不稳 | 显示样本量、置信区间/后验不确定性和最小样本门槛 |
| 长上下文被静默截断 | 请求前窗口校验、实际 Token 记录、截断探针与显式失败 |
| Judge/长上下文费用失控 | 预估成本、Run 预算上限、并发限制和熔断 |
